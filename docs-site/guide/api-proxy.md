# API 代理服务 {#api-proxy}

可选的 API 代理让其他客户端通过 Umeko 已配置的模型服务发起请求。它与 Agent 内部使用的本机通道相互独立。

## 配置模型映射 {#map-models}

在 **设置 → API 代理服务** 先选择供应商，再进入二级菜单为它的模型设置别名。返回后可切换其他供应商，最后统一保存；所有账号的公开模型别名必须唯一。

[![按供应商配置模型映射](/images/model-mapping-zh.png)](/images/model-mapping-zh.png)

*选择供应商后，再编辑模型别名。保存映射后，再单独启动服务。*

## 复制连接信息 {#copy-connection-details}

1. 保存映射，创建一个客户端 API Key。
2. 启动服务，复制界面中的 OpenAI 或 Anthropic **Base URL**。
3. 在客户端填写复制的地址、该 API Key 和映射后的模型别名。

客户端填写的是代理创建的 Key；供应商自己的 Key 留在 Umeko 中使用。

[![API 代理服务与可复制的 Base URL](/images/api-proxy-zh.png)](/images/api-proxy-zh.png)

*先配置连接方式，启动后复制 Base URL。*

## 本机和局域网 {#local-and-lan-modes}

本机模式显示 `127.0.0.1`。保存局域网模式后，复制的地址使用本机可用的局域网 IPv4；没有合适地址时会给出提示。客户端填写具体 IP，`0.0.0.0` 只用于服务监听。

同一网络上的其他设备需要访问时，开启局域网模式并检查系统防火墙。局域网模式监听所有 IPv4 网卡，服务使用 HTTP，请只在可信网络中开启。客户端始终需要 Key 才能访问。切回本机模式会恢复回环地址。

## 管理 Key {#manage-keys}

为不同客户端建立可区分名称的 Key；不再使用时停用或撤销。排障时先确认服务已启动、端口可达、模型别名一致，最后检查供应商本身能否在 Umeko 中正常对话。
