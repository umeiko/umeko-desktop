# 委派子智能体 {#delegate-to-subagents}

任务中有互相独立的部分，可以让主 Agent 委派出去。比如同时阅读不同模块、检查测试、整理资料，再让主 Agent 汇总结论。

> 请委派两个子智能体：一个检查登录流程，一个检查错误处理。先只读分析，最后由你汇总发现和建议。

## 在哪里查看 {#follow-their-work}

主聊天中的任务卡片可点击；右上角的活动头像列表也能打开正在运行的子智能体。对话在右侧展开，展示消息、思考与工具过程。关闭侧栏不会停止任务。

[![子智能体侧栏与消息队列](/images/subagents-zh.png)](/images/subagents-zh.png)

*点击主聊天的任务卡片，在右侧查看独立上下文；补充要求会进入该子智能体的队列。*

侧栏有独立的输入框、草稿、附件和队列：**Enter** 排队，**Ctrl+S** 优先介入；停止按钮只中断这个子智能体。结束后的历史任务也可继续，前提是其原生上下文文件与模型仍然可用。

## 和全局子智能体有什么不同 {#session-subagents-versus-global-agents}

| 类型 | 用途 |
| --- | --- |
| 会话内子智能体 | 当前主 Agent 为这个任务委派的助手 |
| 全局子智能体 Widget | 持久的协调者，用户配置职责、模型与会话连接 |

会话内委派由社区包 `@gotgenes/pi-subagents` 执行，Umeko 适配显示和交互。当前版本不再默认限制为四个；明确配置的社区包并发限制仍有效。并发会增加模型消耗，建议按任务需要控制数量。

全局子智能体通过聊天右下角 Widgets 打开，最多保留 16 个，同时运行 4 个。只有用户在「智能体总线」中连接的会话才能接收任务；关闭页面继续运行，停用 Widget 会停止其代理。

## 更容易得到好结果 {#get-better-results}

给每个助手清晰的范围、输出要求和是否允许写文件。多人修改同一处文件容易冲突，最好分配独立区域，并由主 Agent 做最后验证。
