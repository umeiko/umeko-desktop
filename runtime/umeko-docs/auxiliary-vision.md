# 辅助视觉与 analyze_image

在设置 → 账号与供应商 → 多模态模型选项中，选择已经配置且启用视觉的模型。
默认同时开启自动分析和 `analyze_image`。两个开关独立，可只保留按需工具或只自动分析。
主模型原生支持图片时沿用原生视觉；未选择辅助模型时沿用原有路径。

自动分析只转换发给主模型的请求，原图保留在聊天历史中。辅助模型获得图片、当前问题，
不获得整段聊天历史或工具列表；观察结果是模型生成的数据，不是用户指令。
首次分析的观察和 `analyze_image` 工具记录随会话持久化；后续追问、工具循环、重启或重新打开会话
会复用已保存的观察，不重新发送历史图片。新增附图只分析尚未处理的图片；需要重新读取细节时，
Agent 可显式调用 `analyze_image`。原生视觉模型仍直接接收原图。
自动识图与按需识图均显示在聊天历史的工具调用卡片中，直接展示实际请求的原始模型名、状态、结果和错误；供应商信息放在展开详情中。
不会在输入框上方额外显示识图提示。辅助请求失败会停止当前轮次，取消当前任务会取消辅助请求。

## 配置

用 `models.list` 找到实际模型别名和原生视觉能力，用 `providers.list` 查询其供应商 ID。
`settings.get` 的 `config.auxiliaryVision` 返回当前设置。通过现有工具保存：

```json
{"operation":"vision.configure","arguments":{"config":{"providerId":"实际供应商ID","model":"实际模型别名","autoAnalyze":true,"toolEnabled":true}}}
```

支持局部保存；用 `{"providerId":"","model":""}` 取消辅助模型。配置在后续轮次应用，
不会中断正在执行的任务。供应商网络、证书和凭据均复用该模型的既有设置。

## 按需分析

配置辅助模型并打开工具后，`analyze_image` 位于 **Umeko Desktop** 工具包中，遵循该包和
会话工具开关。仅非视觉主模型使用此辅助路径。不要把它当成新的供应商注册工具。

```json
{"paths":["/absolute/path/screenshot.png"],"question":"读取右下角的错误码，说明哪些文字无法确定。"}
```

`paths` 接受当前工作区相对路径或本地绝对路径，1–4 张 PNG/JPEG/GIF/WebP，每张最多 8 MiB。
工具返回观察文本；不能保证 OCR 或空间判断完全准确。需要进一步细节时，用更具体的问题再次分析。
