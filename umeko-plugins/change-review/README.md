# 本轮变更审查与代码检查点

内置、默认关闭。在插件管理中启用后，任务正常完成、用户中止或主 Agent 进程退出时采集本轮结果。“每轮改动后自动展开”与插件设置页的开关同步，默认开启；关闭面板不会停止采集。后台聊天不会抢占当前聊天的面板。

## 临时审查与持久检查点

临时审查保持原行为：全应用只保留最近一次完成结果，新一轮替换，退出或停用后清理。Widget 首屏为 Timeline，临时结果显示为“本轮变更”。

在右上角 `⋯` 菜单或插件设置页单独开启“保存检查点”后，每轮完成结果才会持久保存。该开关默认关闭，开启前的轮次不会补录。检查点保存会话、工作目录、任务标题、轮次、起止时间、文件覆盖范围、基线和结束状态，只写入本机插件状态目录，不写入项目 `.git`。默认最多 20 份、512 MiB，可通过 `maxCheckpoints`、`maxCheckpointMB` 配置。

重启后历史和当前位置仍可读取。应用或 Agent 中断时只有基线的记录标为“已中断”，不能切换。Widget 上半部分始终显示线性历史，下半部分同时显示所选版本的文件树或 Diff；中间分隔条可拖动调整上下高度。Timeline 整行以黄色表示历史、绿色表示当前、红色表示将被遗弃的未来版本；文件与 Diff 以黄色表示修改、绿色表示新增、红色表示删除。点击任意 Timeline 条目会在下半部分展开该历史轮次的文件树，继续点击文件可查看对应轮次的只读 unified diff，返回键逐级返回文件树。筛选器可只看 Agent 检查点或初始状态，初始状态始终位于列表底部。

## 线性版本与当前指针

一个任务检查点的“版本”指该轮**结束状态**，本轮 Diff 则仍比较开始前的 `base` 与结束时的 `end`。首轮之前另有“初始状态”，内容来自首轮基线，用于撤销第一轮。

Timeline 用“当前 · 标题”标记 `currentId`：

- 完成新轮次后指针移动到最新版本。切换成功后移动到目标版本，并持久化到 `current.json`，重启后不变。
- 只要实际工作区仍匹配当前版本，就可以前进到较新版本或恢复到较旧版本。切回较新版本就是重做，不需要恢复副本嵌套。
- 新修改产生时，放弃当前点之后的未来检查点，再追加新版本。例如 A→B→C 中切到 B 后产生 D，历史变为 A→B→D。
- 新轮次开始和结束都会检查偏离，防止开始时尚未修改、执行后才产生分支。没有文件变化的轮次不生成重复版本，也不放弃未来版本。
- 恢复安全记录仅作为内部操作与故障恢复数据保存，不作为普通“恢复前副本 · …”嵌套条目进入线性时间线。

## 比较范围与限制

基线是**本轮开始前的工作目录 → 本轮结束后的工作目录**，不是 HEAD 或暂存区；包括原有脏文件的本轮增量、新增和删除。相同目录中用户、后台进程或其他会话的并发编辑也会包含在内，不代表每项都由 Agent 修改。仅捕获主 Agent 的完整 loop，包含同一 loop 中工具和子代理在该目录中的修改。

使用系统 Git 的对象、独立索引和 diff-tree。项目的 `.git/index`、分支、历史和文件均不被修改；非 Git 目录也可审查。遵循 Git 忽略规则，原仓库已跟踪的忽略文件仍参与比较；不追踪符号链接、子模块内容、Git 元数据。二进制只显示状态。不联网，不运行项目 hooks、filter、textconv 或自定义 diff 驱动。

每次采集最多 5 秒、4000 个文件、单文件 2 MiB、总内容 32 MiB，Git 枚举输出最多 512 KiB；差异预览最多 48000 字节、1000 行，每行 2000 字符。受限结果明确标为部分覆盖，不能称为完整备份。所有 Git 操作在独立工作进程执行，并行任务最多保留 8 个起始基线。依赖系统 Git；Git 缺失时不阻碍 Agent 正常工作。

## 切换预览与冲突检查

完整检查点的文件树提供“切换到此版本…”操作。预览逐项列出替换、重建、删除、无变化、冲突和未覆盖文件，点击文件可比较当前状态与目标版本：

- 当前工作区匹配任一已知版本时，允许前进或后退，预览标明将覆盖多少版本差异。偏离所有已知版本的修改属于外部冲突；任一外部冲突或未覆盖目标都会阻止切换。
- “没有新修改”根据实际文件哈希判断，外部编辑器和其他会话的变化也会识别，不能只依赖当前界面。
- 同一工作目录存在运行中的前台任务或后台任务时拒绝切换；恢复锁期间阻止该目录的新 Agent 请求和后台启动，不隐式停止会话或已有任务。外部进程不受应用锁约束，因此写入前还会逐文件复核。
- 切换前保存内部恢复安全记录。中途失败会报告已完成、失败和未处理文件，不宣称跨文件原子恢复。
- 切换只修改工作区文件和当前指针，不删除聊天、不改变模型上下文，不修改 Git 暂存区、分支或提交历史，也不使用 `git reset --hard` / `git clean`。

页面组件复用相邻的官方 git-viewer 包，SDK 示例应保持两个示例目录的相邻结构。
