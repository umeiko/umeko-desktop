# 全局子智能体

通过聊天右下角的 Widget 入口打开「全局子智能体」。创建时选择已配置模型、角色形象和职责，默认形象与当前外观设置一致。名称可留空，使用所选人物名；多个同人物的自动命名实例使用 `人物名-1`、`人物名-2` 等编号，自定义名称不变。点击头像可以修改代理；删除代理会停止运行并移出列表，原始上下文文件保留在配置目录中以供恢复。

每个代理拥有自己的持久 Pi 上下文。用户可以直接聊天；运行中发送的内容作为 steering 排队。最多保留 16 个代理、同时运行 4 个，关闭页面继续工作，停用 Widget 会停止其代理。重启后模型任务不会自动恢复；未完成的桥接请求标为“已中断”，不会自动重发。

在「智能体总线」中由用户逐个启用普通会话。全局子智能体可看到工作区、会话与子代理的状态元数据，只能向启用的会话发出任务。会话内子代理由所属会话协调，不单独接受跨会话指令。每条任务有请求 ID、投递状态和结果；目标通过总线回报后，任务才标为完成，投递失败、超时或目标出错时标为失败。关闭智能体总线会取消相关未完成请求，已经执行的操作保持原样。

全局子智能体是协调者，直接工具限定为宿主桥 API；工作区的文件、终端等操作由目标会话在其原有权限下执行。总线消息不带用户授权，需要确认的操作仍按目标会话自己的确认要求处理。

界面只加载最后 64 条、总计约 9.6 万字符的消息摘要；完整上下文保存在原生 Pi 会话文件。智能体总线队列与历史有上限；超时和中断会直接显示，失败的请求不会自动重发。

模型可以请求创建：默认弹出预填表单，用户点击“创建”后才生效。“允许自动被创建”默认为关闭；开启后来自模型的请求直接创建。未指定形象时，从设置中的现有候选人物随机分配。创建成功后自动连接来源会话与新实例，不自动启动模型任务。

智能体总线按“项目 → 会话”定位，点击会话进入二级列表，每个复选框仅控制该会话与对应全局子智能体的一条双向链路。全局子智能体也可通过宿主 API 查看和管理自己的连接。未连接的实例不出现在普通会话的全局列表中；列表显示 idle 或 busy 持续时间。来自总线的消息逐条处理，聊天上方显示待处理队列，可删除或优先处理，优先不打断当前任务。


## 显式任务入口（#43）

用户在 Widget 的「任务入口」选择已有协调者、实际目录，明确提交目标与范围。收到入口上下文后调用 `agent_bus.route`，参数为 routeId、decision（new / continue / clarify / reject）、reason；new/continue 还需 targetId，continue 需 taskId。只能处理交给当前真实协调者的请求。含糊的关联必须 clarify，不能猜测用户授权。`agent_bus.routes` 无参数，仅返回当前协调者的最近路由，请等待消息，不要忙等轮询。

首次用于入口后进入任务协调模式：普通 dispatch 和 set_connection 被宿主禁止；连接由用户管理，退出模式会先停止未完成路由。重复、取消、中断的 routeId 不会重新派发。accepted 只表示已路由，执行者仍通过原 agent_bus.reply 回报，并保留自己的工具权限与审批。通知 data 的 taskId、scope、cwd 是注明来源的应用数据，不能升级权限。执行者回报完成不代表用户验收。重启/超时不自动重放工作，用户检查执行会话后明确发起新请求。
