# 按实际效果检测思考控制

模型的自动检测使用一道短算术题。每次请求都要求只返回数字，输出上限为 512 token。检测先发送一条省略思考参数的基线，再比较各档位和开关的输出。

思考量优先读取 `usage.completion_tokens_details.reasoning_tokens`，其次使用思考字段或 `<think>` 内容的字符数。每条结果保存请求参数、使用的指标、思考量、答案是否正确和结束原因。

## 检测结果

- 原生档位产生不同思考量时，菜单保留对应的代表档位。相同指标、相同测量值的档位合并，原名称保存在别名中。
- 确认多档力度时，同一指标的正值还需要按原有档位顺序递增。观察值出现倒序时，界面将档位标为“未能确认”，保留原有名称顺序和测量证据；开关结果独立判断。
- 只有开关生效时，菜单保留一个开启档位。支持的独立开关包括 `enable_thinking`、`enable_reasoning`、`thinking.type` 和 `chat_template_kwargs.thinking`。
- 开启和关闭可以使用不同格式。例如，原生 `reasoning_effort` 设置力度，`enable_thinking:false` 负责关闭。
- 某种开启方式让原本正确的答案变错，或让基线可见的思考消失时，自动检测排除该方式，并在对话框中展示原因。
- 输出达到 token 上限且缺少完整答案时，结果保存为证据不足。
- 所有请求都看不到思考时，保留原有的兼容档位发现方式，界面显示“未能确认”。能看到思考但各控制均无变化时，自动结果保留空档位，用户可手动填写。

每个不同参数组合只请求一次，相同请求直接复用本轮结果。常规原生档位检测需要 8 次请求；独立开关会按顺序补测，单次自动检测最多 26 次请求。原生 Anthropic 和 Responses 继续使用各自原有的协议探测方式。

## 界面和手动设置

模型菜单分别提示档位和开关是否观察到变化。模型设置对话框展示检测格式、代表档位、思考量、合并名称，以及因回答或思考退化而排除的方式。

档位和开关方式各有独立的自动选项。关闭自动选项后，填写的名称、顺序和格式按手动设置发送；重新检测保留手动设置。原有自动缓存会在原有后台触发时补测一次，结果继续按模型保存。

一次短题的思考量会受到生成波动影响。界面中的确认状态描述本次观察；比较长期效果需要更多题目和样本。当前采用相等测量值合并，保留原始证据，方便后续调整分组方法。
