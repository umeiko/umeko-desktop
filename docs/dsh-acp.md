# DeepSeek Harness 可选后端

Pi 仍然是默认后端。新聊天打开输入框的模型菜单，在「会话后端」选择 **DeepSeek Harness**，然后选择已配置的供应商与模型。聊天开始后后端固定；如需更换，创建新聊天。

## 安装与检查

在 **设置 → Agent → DeepSeek Harness** 中填写官方 dsh 的安装目录、npm 入口或 `lib/bin.js`。Windows 的 npm 安装通常包含 `node_modules\@deepseek-ai\dsh\lib\bin.js`；全局安装也可选择 `dsh.cmd`。留空时依次查找 Umeko 管理的安装和 PATH。

「检查」会确认文件和官方版本，再启动 `--profile acp` 并执行 ACP initialize。要求 `0.2.2-rc.1` 或更新版本；检查不向模型发送问题。显式填写的错误路径会直接提示修正，避免运行与设置显示不同的安装。

检查成功后默认显示入口文件名与版本，可展开查看完整路径；手动配置的路径仍可直接编辑。

「下载运行时」使用随 Umeko 分发的 Node/npm，将官方 npm 包 `@deepseek-ai/dsh@0.2.2-rc.1` 安装到应用数据目录中的 `dsh/runtime/dsh-0.2.2-rc.1`。下载沿用应用 npm 证书、配置和代理设置，包从官方 npm registry 获取。进度按下载、检查、保存阶段显示；取消或失败会清除未完成的临时安装，保留原有版本。

## 模型来源与 API Key

**默认无需为 dsh 另填 API Key。** Umeko 会把现有模型列表和别名提供给 dsh，并通过应用已有的内部 API 代理调用供应商。模型菜单与其他 Umeko 会话一样，使用已配置的模型；切换后由同一个 Gateway 完成别名映射、协议转换和供应商调用。API Key 型供应商、已登录的 SDK 供应商插件（包括 CodeArts）都使用这条路径，仍需在 Umeko 中完成原有登录或配置。

内部入口在 Umeko 启动时已经自动建立，Pi 也使用它；「API 代理服务」页面的开关控制对外入口。因此该开关关闭时，默认 dsh 仍可使用内部代理，无需创建对外 API Key。内部入口异常关闭时会提示重新启动 Umeko。

默认模式不向 dsh 传供应商 API Key、登录凭据或上游地址。它只获得本机代理地址、模型别名，以及 Umeko 每次启动生成的内存认证令牌；令牌只通过子进程环境传递，不写 profile 或聊天内容，应用退出后失效。旧的逐供应商 `UMEKO_DSH_KEY_*` 注入路径已删除。

在 **设置 → Agent → DeepSeek Harness** 勾选 **「使用 dsh 自己的模型和 API Key 配置」**，可改用 dsh 自身的 **ACP profile 及 home 全局配置**。Umeko 此时不注入供应商或初始模型，不读取、复制其密钥文件；由官方 dsh 按正常 `DSH_HOME`（未设置时为 `~/.dsh`）加载配置与凭据。仅放在 dsh web/desktop profile 中的独立配置不会自动合并到 ACP，自己的 ACP 默认模型需要可用。首次连接使用它的默认模型，连接后模型菜单显示官方 ACP 返回的模型选项，可直接切换。

这个开关默认关闭，模型来源在会话开始后固定；修改后请新建 dsh 会话，已有会话继续使用原来源。Umeko 的显示历史和该会话的原生上下文仍保存在应用数据目录，使用自有配置也不会把上下文写进其他 dsh 会话。自有配置模式下，供应商登录、密钥与网络配置由 dsh 自己管理，Umeko 的代理模型设置不应用于它；工具权限、审批和停止方式保持相同。

## 工作目录与工具权限

dsh 使用会话所在项目目录作为初始工作目录和工作区写入边界。权限模式来自 **设置 → Agent → 工具执行权限**，与 Umeko 原有的全局设置相同；保存后会同步到已经打开的 dsh 会话，包括后台会话。不会为了切换模式重启会话。模式更新失败会结束该运行时并提示错误，避免继续使用旧设置。

| Umeko 模式 | dsh 原生配置 | 执行行为 |
| --- | --- | --- |
| 全自动（`auto`） | `workspace-write` + `approval: ask` | 工作区内的普通读写、命令直接执行；需要越界权限时使用 dsh 的单次审批。 |
| 每次询问（`ask`） | 同上，另通过官方工具前置审批接口询问 | 读取、搜索直接执行；写入、编辑、补丁、shell 命令以及明确标为修改性的工具，每次执行前询问。原生越界请求只询问一次。 |

`approval: ask` 在 dsh 中表示“需要授权时询问”，自身并不表示“每个工具都询问”。Umeko 加载一个小型 profile 插件，通过官方 `tools/pre-execute` 接口实现后一种模式；聊天、取消和审批仍使用官方 ACP。插件也通过官方权限服务将新建和恢复的会话对齐到 `workspace-write`，不修改 dsh 包或其会话数据库。

「本次允许」只授权该次请求，不改变全局模式或后续操作的边界。工作区外的文件操作可能先在工具卡中显示 dsh 的沙盒拒绝，随后由模型携带升级请求申请本次授权；拒绝后该操作不执行。首版不提供永久的完全访问授权，也不复用 Pi 的会话危险操作授权或全部风险分类规则。

这里的工作区边界约束写入，不是文件读取隔离；工作区外正常可读的文件仍可按 dsh 原生规则直接读取。原生文件工具还允许写入固定的系统临时目录，当前版本没有关闭这一例外的配置；Windows shell 不支持额外可写目录。因此这里采用官方最接近的工作区策略，不能承诺所有工作区外的访问都一定弹窗。符号链接或目录联接按实际指向的位置判断，不能用工作区内的链接绕过写入边界。

Windows 的 shell 沙盒使用受限令牌、Low 完整性级别和目录 ACL 授权。项目目录需要当前用户拥有完全控制权限，包括 `WRITE_DAC`、`WRITE_OWNER`；只有“修改”权限的目录，以及某些只向 OWNER RIGHTS 授权的私有临时目录，可能无法正常运行沙盒。此时 pwsh 可能无法进入项目目录，或在启动前报告授权失败。请使用正常继承当前用户完全控制权限的项目目录；Umeko 不自动修改已有目录的 ACL，也不自动关闭沙盒。dsh 自身正常挂载工作区时会添加原生沙盒所需的 ACL 和 Low 标签。

上述配置对应固定版本的 `dsh-base/cordis.patch.yml`、`dsh-sandbox-policy`、`dsh-tools` 和 `dsh-sandbox-windows-acl` 随包文档。标准 ACP 当前没有工具权限模式设置项，因此模式同步使用独立的本地进程控制通道，不伪造 ACP 配置选项，也不向模型发送权限切换消息。

## 当前支持范围

- 文字聊天、思考块、带参数和结果的工具卡、上下文用量。
- 工具请求在现有审批窗口中选择「本次允许」或「本次拒绝」。不提供整个聊天的长期授权。
- 停止通过 ACP cancel 发出。运行中按 Enter 发送的消息按顺序排队；停止后未发送的消息回到草稿。聊天中会以淡色状态行标明上一请求已停止，并在下一条消息前用独立内容块告知运行时只处理新消息，除非用户明确要求继续。此状态跨重启保存，下一请求失败时也会保留；用户自己的消息原文不变。停止不会删除此前历史。
- 默认复用 Umeko 的模型及已有内部 API 代理，包括已登录的 SDK 供应商插件；可选使用 dsh 自身 ACP 配置，详见上文。
- 模型与思考强度通过运行时提供的 ACP 配置选项切换，可选档位取决于模型与运行时。
- Umeko 单独保存用于显示的聊天历史；重新打开时先显示历史，再恢复同一 ACP 会话。显示历史和 dsh 的上下文目录都需要保留。

官方 dsh 当前在消息提交后发送整条正文和思考，界面不会逐字输出。首版不提供子智能体、上下文压缩、会话分支、运行中插话（steering）或图片输入，也不管理 dsh 插件。Pi 的工具、扩展、MCP、Skills 等设置不自动应用到 dsh。该后端使用官方 `--profile acp`，不运行社区 ACP 适配器。

达到本轮模型输出上限时，会显示中文提示并结束该轮；首版不会自动续写。
