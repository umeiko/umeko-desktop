The side browser is a single Qt WebView loaded by `WebSurface.qml`. A fresh successful `submit_to_chatbox` tool event with an HTTP(S) URL expands it automatically. A user can also click an already-delivered URL card to open the pane. The host verifies the active session and ignores history replay, background sessions, ordinary assistant text and other tools. Repeated submissions replace the current URL, or reload the same page. Closing destroys the view; URL cards have three context actions: open in the default system browser, copy the URL, and attach the URL to the current chat without changing its draft. Attachment chips retain their URLs when sent or restored from history. There is no separate toolbar action or keyboard shortcut to open an empty pane.

`PidMotion` controls the panel width, including closing to zero. The native view is hidden during motion and while a modal overlay is displayed. It stays alive during ordinary navigation and overlays, preserving back/forward history, and is destroyed when dismissed or the session changes.

On Linux the base package carries only the small Qt WebView frontend. The WebEngine backend, renderer helper, resources and Qt dependencies are a separate, pinned ZIP. `runtime/webview-component.json` identifies its immutable resource tag, size and SHA-256. Both editions share the per-user component directory and validate its Qt version before loading it at startup. Source development can override that directory with `UMEKO_WEBVIEW_COMPONENT_DIR`.

Component instructions are returned by the submit tool only if a URL is submitted without the Linux engine. They are not injected into the system prompt, tool description or application UI. There is no extra browser automation, download or component administration tool. The response includes the official release page, direct ZIP URL, checksum, destination and activation JSON. The Agent uses its existing tools after verifying the ZIP. Restart is manual, so installing a component never interrupts ongoing Agent work.

Build the reviewed component with `python scripts/webview_package.py --qt-root /path/to/Qt/6.10.2/gcc_64 --engine release-assets/webview --registry runtime/webview-component.json`. Update the same registry in both editions whenever the resource tag changes. The manual `webview-component.yml` workflow checks the pinned registry before publishing a separate prerelease resource tag, keeping it out of normal app update discovery.

The Python build stages only WebView frontend files from the checksum-verified matching PySide wheel. It does not install or bundle the full PySide Addons distribution. Its tray listens only to the main window, avoiding Python wrappers around transient Chromium objects in a global application event filter.

The same panel can show local Markdown, source code and plain-text artifacts through `DocumentSurface.qml` and the bounded background `DocumentPreview` reader. This mode never loads WebView or requires the Linux component. A shared left divider resizes web/document previews directly while opening/closing retains PID motion. First focus on the web address field selects its entire URL. See `chatbox-media.md` for limits, cancellation and fallback behavior.
